# Quillmarc waitlist

Static landing page and brand guidelines for Quillmarc (working name): monthly investor updates written from live Stripe data. Palette: Sapphire Lounge (Midnight Navy #102542, Sapphire #1E3A5F, Champagne #D8C3A5, Ivory #FAF8F5, Gilt gold #DDB040).

No build step. `index.html`, `styles.css`, `app.js`, `config.js`, `brand/` and `assets/` deploy as-is.

- `/` the waitlist page
- `/brand` the brand guidelines (idea, mark, colour, type, voice, imagery, components, motion, files)
- `brand/tokens.css`, `brand/tokens.json` design tokens; the page and guidelines both use them

## Deploy on Vercel

1. vercel.com, Add New, Project, import `jithujsam-cloud/Saas-idea`.
2. Framework preset: Other. Leave build command and output directory empty (root directory `./`).
3. Deploy. Every push to the production branch redeploys.

`vercel.json` turns on clean URLs and caching for `assets/`; `.vercelignore` keeps the design tooling, migration and screenshots off the site.

## Run locally

```sh
python3 -m http.server 8000
# open http://localhost:8000
```

## Connect Supabase

1. Create a Supabase project.
2. Run `supabase/migrations/20261020000000_create_waitlist.sql` (SQL editor, or `supabase db push`).
   It creates `public.waitlist` with row level security: the public key can insert, and cannot read, update or delete.
3. Put the project URL and publishable (anon) key in `config.js`.

Submissions go straight to the Supabase REST API (`POST /rest/v1/waitlist`). A repeat email counts as success, so people who sign up twice see the same calm confirmation. A hidden honeypot field drops simple bots.

Read signups in the Supabase dashboard, or with the service role:

```sql
select created_at, email, company, investor_count, current_method from public.waitlist order by created_at desc;
```

## Brand assets

`assets/logo/` holds the primary wordmark (Quillmarc, its i dotted with a gold square) in ink, reverse, sapphire and one-colour versions, the pen-written Q symbol, app icons, a social lockup and a favicon that follows the colour scheme. All are generated by `python3 brand/tools/build_logos.py` from `brand/tools/mark.json` and the wordmark outlined from Newsreader Regular, so no file depends on an installed font. The page inlines the same paths as SVG symbols, so the logo follows light and dark mode.

## Design tooling

The first version was art-directed with the `design-taste-frontend` skill (`.claude/skills/`); the current product-led design deliberately departs from some of its house rules (cards, kickers, shadows on floating product UI). Its lint and inspector are still useful for overflow, contrast and headline checks:

```sh
node .claude/skills/design-taste-frontend/scripts/lint.mjs index.html styles.css app.js
node .claude/skills/design-taste-frontend/scripts/inspect.mjs index.html --allow mono,font-count
```

`--allow mono,font-count` reflects two brand rules: Geist Mono is kept for figures, and the brand uses three faces.
